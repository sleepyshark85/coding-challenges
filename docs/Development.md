## AI Collaboration in Implementation
This document describes how I collaborated with AI to implement the challenge requirements. 
I used Claude Sonnet 4 for everything.

For all the prompts, I always do a throughout review and cleanup unecessary code.

### Prompts

#### Generate domain models
I asked Sonnet 4 to generate the following domain models for my application: Quiz, QuizQuestion, UserQuiz, UserQuizQuestion. The following instructions are given:
- I want always-valid models
- Let's do the validations in the ctor for simplicity (Explaination: This implicitly indicates that exceptions will be thrown if the validation failed. Not the best approach, but the quickest approach).
- I don't want to use CQRS (Over-complicated for this project)

Manual steps:
- Cleanup the code

#### Generate EFCore context & entity type configurations
I asked Sonnet 4 to generate implementations of `IEntityTypeConfiguration` for my models (I used domain models directly as entities for simplicity,  it actually caused a little trouble for me during the implementation, but anyway!). The following instructions are given:
- I want to use backing fields for the navigation properties. (Explaination: This will prevent them to be replaced by the consumers).

Manual steps:
- Beside from reviewing the code, generate EFCore migrations and database to make sure everything works as intended.

#### Generate controllers
I asked Sonnet 4 to generate QuizManagementController and QuizController with the following instructions:
- Only generate code for the follow actions: Create quiz, Join quiz and Submit answer.
- Only generate action signatures, do not implement them.
- Make sure we follow API design best practices for the enpoints, documentation ...
- I want to use OpenAPI for API documentation, not Swagger.

Manual steps:
- Integrate with OpenAPI
- Test and review the endpoint documentation on http://localhost:5001/scalar

#### Generate initial WebSocket server setup (Yes, I did ask them this!)
I implemented everything on Elsa.QuizAPI before starting with Elsa.WebSocket.

I asked Sonnet 4, based on the requirements and the code I had on Elsa.QuizAPI, to generate a WebSocket setup on Elsa.WebSocket project to manage websocket connections to quizzes.

Manual steps:
- Most of the implementation in `QuizConnectionManager` is generated by Sonnet 4. I only need to make sure I can quickly retrieve the connection of a specific user.

#### Generate test client
I asked Sonnet 4, based on the requirements, and the code I had on Elsa.QuizAPI and Elsa.WebSocket, to generate a html page to test the socket connection. You can find it here [test.html](../src/Elsa.QuizSocket/test.html).

Manual steps:
- Make sure it connects to the right port, endpoint

#### Generate Dockerfile and docker-compose
I asked Sonnet 4 to generate the Dockerfile for my applications and a docker-compose with the following components:
- Elsa.QuizAPI
- Elsa.WebSocket
- postgres
- redis

Manual steps:
- Refactor the Dockerfile
- Manually add adminer, redisinsight

### Notes
- The manual steps I noted above don't include code that I wrote myself.
- I usually check the official documentation of the frameworks/libraries being used on the AI-assisted code to make sure I understand every line of code.
- I find AI excels at generating concrete implementation of a library or framework(EFCore, SignalR, OpenAPI documentation, Dockerfile, docker-compose ...) where the code is mostly the same across applications.
